## 签到可行性判断

签到不是单一接口：普通签到在不要求额外数据时可由电脑发出请求；签到码、手势、二维码和位置活动需要不同参数。客户端能提交这些参数，不等于服务器一定接受，也不证明能够绕过在场验证。动态二维码会更新，位置可能带额外校验，人脸/照片无法仅用普通签到请求替代。

实现依据为上游 [签到函数](https://github.com/Samueli924/chaoxing/blob/45d2106b16764231c2de2038fb042e71b23d878f/api/base.py)、[xxtSignApi](https://github.com/MetaQiu/xxtSignApi) 和 [chaoxing-signin](https://github.com/cxOrz/chaoxing-signin) 的参数说明。它们是开源观察，非平台稳定官方 API 合约，平台变更后可能失效。

本版没有生成现场签到码、伪造生物特征、修改GPS或规避设备校验。签到界面按实际条件提交，失败/缺参返回明确结果；不宣称“任何活动均可不在场签到”。

## 后端协议和提交控制

第三方源码和 Python 3.13 在独立进程运行；自己的题型/字段适配在 `study_worker.py`。使用服务器页面中的真实题目ID、选项和隐藏字段，提交前重新读取并比较题目，避免随机题或教师修改造成答案错配。

源码字体资源通过原项目绝对路径只读加载，私有工作目录不依赖复制资源。HTTP成功、服务器业务接受、回读确认分别表示，只有核对的状态才标作完成。回读会忽略脚本中的“提交成功”文字，也不把仍可编辑的作答表单当作提交完成。

同一作业/课程/活动的活跃写任务不重复排队；相同已完成请求短时间内拦截连点。关窗会请求停止，worker还监视父进程身份，异常退出后不会继续成为不可管理的刷课进程。已发送的远端请求不能因本地取消而撤销。

## AI 与数据处理

每题发送题干、选项、关联题图及实际检索资料，不发送学习通会话、账号或手机内容。图片字节只发送给所选模型，搜索只接收文字查询。模型回答中的来源必须来自该题搜索结果。模型服务与搜索服务的HTTP重定向被拒绝，避免认证资料被转发到其他地址。

`status=ok` 是结构和题型校验，不是事实正确的保证。搜索失败会保留明确失败状态；实际使用搜索时要求有可核验来源，用户检查后仍可手动编辑并发起保存/提交。
