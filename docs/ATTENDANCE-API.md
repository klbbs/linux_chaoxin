# 学习通签到接口依据与验证状态

小程序仅用于界面设计参考：活动筛选、折叠详情、地图选点、常用位置和按类型填写参数。应用不调用小程序服务，不使用其账号或代理接口。课程与活动使用本人的学习通网页会话，真实请求发往学习通域名。

## 数据与请求来源

| 功能 | 学习通路径 | 当前依据与验证状态 |
|---|---|---|
| 课程列表 | `mooc2-ans.chaoxing.com/mooc2-ans/visit/courselistdata` | 通过固定上游源码读取，已实际只读获得52门课程。 |
| 课程活动 | `mobilelearn.chaoxing.com/v2/apis/active/student/activelist` | 已用真实会话只读获得一门课程15项活动。 |
| 预签页 | `mobilelearn.chaoxing.com/newsign/preSign` | 学习通页面入口，由后端在提交前加载；页面可提出登录、验证码等要求。只读页面检查与实际签到成功是不同证据。 |
| 签到提交 | `mobilelearn.chaoxing.com/pptSign/stuSignajax` | 请求直接连接学习通；路径及普通签到参数参考固定上游实现，各签到类型线上提交尚未逐类验证。 |

对应实现：`study_worker.py` 的 `Worker.execute`、`sign_parameters`，以及固定后端 `api/base.py` 的 `get_course_list`、`get_activity_list`、`pre_sign`、`sign_in_normal`。来源为 [Samueli924/chaoxing 固定提交](https://github.com/Samueli924/chaoxing/blob/45d2106b16764231c2de2038fb042e71b23d878f/api/base.py)。额外参数发现参考 [MetaQiu/xxtSignApi](https://github.com/MetaQiu/xxtSignApi)，这些项目属于接口发现线索，不能替代当前学习通响应核验。

## 字段适配

活动列表的名称使用 `nameOne` / `nameTwo` 等实际字段；时间支持秒或毫秒时间戳，按北京时间显示。`type=2` 表示签到，`status=1/2` 对应进行中/已结束，来自上游枚举并与当前返回对照。明确非签到的活动不进入签到列表；缺失或未知状态保留为未知。`userStatus` 暂不解释为“已签到”，避免猜测。

界面按 `otherId` 识别模式：`0`普通、`2`二维码、`3`手势、`4`位置、`5`签到码；缺失或未知时要求手动选择。固定上游枚举明确提供0/3/4；2/5的语义还需当前学习通页面或运行证据核对，不能从参考小程序界面推出。本次可用样本均为已结束活动，读取预签页没有取得可确认模式的表单（一个返回既有签到结果页）；因此没有把2/5语义提升为已验证。

提交使用学习通需要的活动、课程、班级和本人身份字段；签到码与手势使用 `signCode`，位置使用经纬度、`address`、`ifTiJiao`，二维码使用有效内容中的 `enc`。动态二维码、验证码、附加设备检查或服务器协议变化可能要求额外数据。现有离线测试只验证参数构造、字段传递和结果处理，不能证明平台实际接受。

地图服务是独立的OSM/Photon，接收地点搜索和地图视野，不接收学习通会话或活动参数。默认返回GCJ02，明确标为WGS84的输入在服务层转换一次；这一约定与数学测试不构成学习通当前全部位置活动的坐标协议证明。没有改动手机GPS，详见 [地图说明](MAPS.md)。

## 成功判定与后续核验

仅将学习通明确返回 `success`、`您已签到过了` 或 `已签到` 记录为成功；其他返回原文提示处理。HTTP 200、预签页加载、地图确认或常用位置保存均不能视为签到成功。

本次未发送真实签到请求。线上写入成功、位置校验、动态二维码有效期、人脸/照片和设备验证仍需要使用具体活动分别核验；不将界面完成和离线测试通过写成线上接口全部验证完成。
